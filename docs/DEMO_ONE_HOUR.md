# MASAR — خطة Demo خلال ساعة

التاريخ: 2026-11-03 (الرياض). لا SQL أو إنشاء مستخدمين أو كتابة بيانات مستضافة قبل موافقة المالك. لا يلزم تعديل كود الميزات للوصول إلى المسار الحالي.

المسار الأقصر: تشغيل React وFastAPI والعامل على جهاز المالك الذي نجح منه اختبار Cloudflare، واستخدام Supabase الحالي. ليست تجربة غير متصلة: الهوية والبيانات والملفات على Supabase، والاستدلال والفهرسة عبر Cloudflare Workers AI. نطاقات مشروع Supabase وapi.supabase.com وapi.cloudflare.com أصبحت مسموحة في Codex، مع إبقاء الشبكة مقيّدة. جاهزية التنفيذ المستضاف تتطلب صلاحيات metadata والتطبيق وإعدادات التطبيق الخاصة؛ لا تكفي الموافقة أو سلامة الاتصال وحدهما.

## إعدادات خاصة مطلوبة

- frontend/.env: VITE_API_BASE_URL=http://localhost:8000، VITE_SUPABASE_URL، VITE_SUPABASE_PUBLISHABLE_KEY.
- backend/.env: MASAR_SUPABASE_URL، MASAR_SUPABASE_PUBLISHABLE_KEY، MASAR_SUPABASE_SERVICE_KEY، MASAR_CLOUDFLARE_ACCOUNT_ID، MASAR_CLOUDFLARE_API_TOKEN.
- استخدم إعداد development وCORS الافتراضي لـ localhost:5173، وMASAR_AUTH_REDIRECT_URL=http://localhost:5173/reset-password، وMASAR_RETRIEVAL_MODE=hybrid، وMASAR_DEMO_ENABLED=false.
- أكّد Workers Free قبل MASAR_CLOUDFLARE_FREE_PLAN_CONFIRMED=true. نموذج الإجابة الافتراضي @cf/meta/llama-3.1-8b-instruct-fp8-fast والفهرسة @cf/baai/bge-m3 (1024). لا تغيير فوترة أو بديل مدفوع.
- لا تستبدل ملفات .env الموجودة ولا تضع سرًا في VITE_ أو Git أو المحادثة. القوالب الحالية تكفي؛ املأها خصوصيًا فقط.

## بعد الموافقة فقط

افحص مخطط المشروع وتاريخ migrations قبل أي كتابة. ملفات supabase/migrations الخمسة هي المصدر؛ طبّق غير المطبق فقط. إذا كانت الجداول موجودة دون تاريخ مطابق، لا تعِد تشغيل الملفات الأصلية فوقها. لا تستخدم supabase/tests على المستضاف. migration4 ينشئ company-documents خاصًا؛ لا تنشئ bucket عامًا يدويًا.

أنشئ مستخدم Auth من Dashboard مع تأكيد البريد مباشرةً إن كان جديدًا؛ لا تنشئ مستخدمًا مكررًا إذا كان المناسب موجودًا. احتفظ بكلمة المرور خارج المحادثة. ثم من backend، بعد اكتمال migrations:

```sh
uv run python -m scripts.bootstrap_company --admin-user-id AUTH_USER_UUID --company-name 'ACTUAL COMPANY NAME' --display-name 'ADMIN NAME' --confirm-provision
```

هذه الأداة تُشغّل محليًا لكنها تكتب شركة وملف Admin في Supabase؛ ليست خطوة محلية بحتة. ترفض العضوية الموجودة ولا تتجاوزها.

شغّل ثلاث نوافذ طرفية:

```sh
# backend
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

```sh
# backend، بعد جاهزية الإعدادات والخدمات
uv run python -m app.worker
```

```sh
# frontend
npm run dev -- --host 127.0.0.1
```

افتح http://localhost:5173. ارفع TXT UTF-8 صغيرًا بنص معتمد، دون معلومات حساسة؛ اجعل الوصول لمديري الشركة فقط في الاختبار الأول. لا حاجة لإنشاء موظفين أو أقسام أو SMTP لإتمام هذا السيناريو. PDF يجب أن يكون نصيًا غير ممسوح/مشفّر. إن بقيت الوثيقة processing/draft، افحص العامل قبل السؤال؛ لا تعتبر الرفع وحده فهرسة ناجحة.

معيار النجاح: published مع مقاطع، ثم جواب answered وdemo=false من Llama مع مصادر غير فارغة واقتباس حرفي يطابق المقطع، وإمكانية فتح المصدر وسجل المحادثة. الاختبارات المحلية السابقة لا تثبت هذا النجاح الحي.

الموافقة المطلوبة تغطي بالتحديد: migrations الناقصة وbucket الخاص، إنشاء Auth Admin وربطه بشركة، وكتابة المستند والمقاطع والمتجهات والمحادثة الخاصة بالـ Demo، واستدعاءات Workers AI ضمن Free. لا حذف/Reset/Deploy/Merge أو ترقية مدفوعة. اسم الشركة والمدير وبريده يُحدَّدها المالك؛ لا تُخترع بيانات شركة أو سياسات.

## آخر تحقق محلي

نجحت131 اختبارات Backend و20 اختبار واجهة و24 اختبار متصفح، مع lint/typecheck/format وproduction build. ضُبطت عناوين الخدمات العامة فقط في ملفات .env المستبعدة، دون استبدال قيم موجودة أو إدخال مفاتيح. API والواجهة قيد التشغيل محليًا؛ العامل لم يبدأ لأن المخطط وبيانات الوصول لم يُتحقق منهما بعد. راجع DEMO_ACCESS.md للعوائق الدقيقة.
